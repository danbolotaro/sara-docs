Instalação

Como configurar e rodar o SARA na sua máquina.

Requisitos

  • Node.js 20 ou mais recente
  • npm (já vem com o Node)
  • Uma conta no Supabase (o plano gratuito serve)
  • Git

1. Clonar o projeto

git clone https://github.com/danbolotaro/sara-project.git
cd sara-project
npm install

2. Criar o banco no Supabase

Crie um projeto novo no Supabase, abra o SQL Editor e rode o script abaixo. Ele cria as duas tabelas usadas pelo sistema. 

create table person (
  id          uuid primary key default gen_random_uuid(),
  name        text not null,
  gender      text check (gender in ('Masculino', 'Feminino')),
  age         integer,
  hometown    text,
  story       text,
  contacts    text,
  created_at  timestamptz not null default now(),
  updated_at  timestamptz not null default now()
);

create table encounter (
  id              uuid primary key default gen_random_uuid(),
  person_id       uuid not null references person(id) on delete cascade,
  date            timestamptz not null,
  location        text,
  prayer_request  text,
  notes           text,
  contacts        text,
  created_at      timestamptz not null default now(),
  updated_at      timestamptz not null default now()
);
O on delete cascade faz com que, ao excluir uma pessoa, os encontros dela também sejam apagados.

3. Configurar as variáveis de ambiente

No Supabase, vá em Project Settings → API e copie a URL do projeto e a chave anon. Depois crie um arquivo .env.local na raiz do sara-project: 

NEXT_PUBLIC_SUPABASE_URL=https://seu-projeto.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=sua-chave-anon

Esse arquivo já está no .gitignore, então não vai para o repositório.

4. Executar

npm run dev

Abra http://localhost:3000. A página inicial leva direto para a lista de pessoas.

Versão de produção

npm run build
npm start

Testes

Os testes end-to-end usam Playwright e rodam contra o banco configurado no .env.local. Na primeira vez, instale o navegador: 

npx playwright install chromium

Depois é só rodar:

npm run test:e2e          # roda os testes no terminal
npm run test:e2e:ui       # abre a interface do Playwright
npm run test:e2e:report   # mostra o último relatório
Os testes criam e apagam registros de verdade. Prefira usar um projeto do Supabase separado para testes, e não o de uso real.

Problemas comuns

  • Erro 500 nas listas: confira se as variáveis do .env.local estão certas e reinicie o npm run dev depois de alterá-las.
  • Listas sempre vazias: se o RLS (Row Level Security) estiver ativado nas tabelas, crie políticas que liberem leitura e escrita para a chave anon, ou desative o RLS em ambiente de desenvolvimento.
